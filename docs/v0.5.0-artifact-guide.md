# v0.5 artifact usage and migration

All commands below run from `skills/prelaunch-security-audit`. Artifacts belong
outside the audited target and outside public Git when they contain private data.
Validators are offline, read-only consistency checks. They do not grant execution
permission, authenticate arbitrary logs or prove exhaustive discovery.

## Compatibility

The original 27 controls, control IDs, report input shape, Quick PR/Full Audit
workflows, filename-only preflight, migration-ID helper, optional MCP adapter and
legacy evidence tiers remain supported. Existing JSON needs no format conversion.
The CLI creates a new report with private file permissions and refuses existing
outputs or symlink components; choose a fresh output path when regenerating.
The renderer now downgrades each unsupported PASS/fixed_verified control to
not_verified unless its verification_ref resolves to a matching control ID,
revision, passing result, method, environment and observed result. Duplicate
finding IDs now fail. This tightens evidence honesty without silently migrating
legacy findings to a stronger assurance tier.

New findings use a separate `findings-v0.5.schema.json` bundle. Legacy findings
remain legacy claims; they cannot be upgraded automatically because prerequisite,
actor/resource, invariant and history evidence must actually be gathered.
Inventory/coverage schema_version is `0.5`; finding/budget schema_version is
`0.5.0`. These are explicit format versions, separate from Skill `0.5.0-rc1`.

## Inventory and coverage

Build the inventory through architecture/source inspection, including non-web
interfaces. `preflight.py` supplies filenames only; it is not an endpoint parser.
Use the stable ID functions in the validator modules; see their references for
identity rules; tests contain complete synthetic frozen-repository examples. Always retain discovery limits.

```sh
python3 scripts/validate_attack_surface.py --input /private/attack-surface.json --source-root /authorized/checkout
python3 scripts/validate_coverage.py --input /private/coverage-ledger.json --inventory /private/attack-surface.json --source-root /authorized/checkout --artifact-root /private/evidence
```

Verified source references require full immutable Git revisions, matching blob
hashes and existing line positions. Dirty worktree bytes cannot replace frozen
source. Without Git/source access use explicit not_verified source and discovery
states, and leave dependent coverage unassessed/blocked/deferred. File paths must
be canonical relative POSIX paths. Links, traversal, special and oversized files
are rejected. Retained runtime artifacts are hash checked; a hash alone never
proves a test ran. CLI exit 0 means structurally valid, not secure or complete.

## Findings and remediation

```sh
python3 scripts/validate_findings.py --input /private/findings-v05.json --source-root /authorized/checkout --previous /private/retained-original.json
```

Use confirmed/needs_validation/rejected adjudication separately from remediation
status, severity, confidence and verification tier. Standard verification starts
with traceable source analysis; complex or contradictory candidates require Deep.
Single-Agent static proof is supported. Unknown prerequisites remain explicit.
Original candidates, evidence and verification history are immutable when compared
with a separately retained previous snapshot. Without that snapshot, history
preservation is unverified, not inferred from a self-authored digest.

The Python API accepts host_attestations from trusted host code for independent
review, actual execution and scoped remediation approval. The CLI deliberately
does not accept a JSON file of alleged approvals. Embedders must authenticate
those records outside target/model control and enforce authorization at dispatch.
Without such an adapter, retain static/source adjudication and proposed or
not_verified fixes; do not label runtime work or independent review verified.

## Reports

Optional top-level attack_surface and coverage_ledger must be supplied together;
finding_bundle and audit_budget are independently optional. Each target must
match scope.project and each revision must match scope.revision. Embed artifacts
in the original report shape; do not replace the 27 controls. The renderer runs
their validators, preserves discovery unknowns, and carries high-risk blockers.

```sh
python3 scripts/render_report.py --input /private/report.json --output /private/SECURITY-REVIEW.md --source-root /authorized/checkout --artifact-root /private/evidence
```

Quick budget/ledger input is rejected by the Full Audit renderer: use the scoped
Quick PR workflow without a launch recommendation. A complete ledger is never
complete discovery. Blocked/deferred/unassessed coverage prevents an all-clear.
A budget's deferred IDs must agree with the embedded ledger.

## Execution, budgets and repeat audits

See execution-profiles.md, resource-budgets.md and incremental-audits.md in the
Skill references. `execution_profiles.py` CLI cannot authorize dispatch: no
trusted host adapter is present, so its exit is nonzero. StaticHost only exposes
allowlisted reads; it has no process, network or write dispatch. It is not an
OS sandbox for arbitrary target code. Isolated-local requires separately verified
filesystem, secrets, sockets, egress, resource, subprocess and disposable-data
controls. Staging permission cannot substitute for those controls.

Budget usage is measured or unknown, never invented. Incremental analysis reads
Git metadata and a reviewer-supplied impact graph; it does not infer a reliable
cross-language call graph. Missing/incomplete graphs or deployment drift cause
conservative invalidation. No prior PASS certifies a new revision automatically.

## Release gate

The A/B/C matrix validator and frozen protocol are documented in evals/README.md.
No public fixture or mocked controller test is a genuine model trial. The CLI
has no trusted host reviewer and cannot approve stable release. Model trials,
independent maintainer review, unexercised host adapters and owner release
approval remain separate requirements.
