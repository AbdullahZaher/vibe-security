## 1. Baseline failure (before any fix)

Command, from the repository root:

```sh
python3 -m unittest discover -s skills/prelaunch-security-audit/tests -v
```

Observed at `686b968` on this macOS host:

- 219 tests
- 2 failures, 6 errors, 1 skipped
- exit 1
- raw log SHA-256: `5b30ed1d1c569bb2569293af80a2f915d3e39674e86dbdab494bf0d3888336ef`

All eight failures traced to the same cause: the artifact reader and writer
walked every path component with `O_NOFOLLOW`, including macOS's root-owned
system symlink `/var` -> `/private/var`. `tempfile` returns `/var/folders/...`,
so valid test artifacts could not be read or created. Example:

```text
NotADirectoryError: [Errno 20] Not a directory: 'var'
```

This is a portability defect, not a target vulnerability. The prior CI run on
Linux (Python 3.13.18) did not expose it because `/tmp` is not a symlink there.

## 2. Findings and fixes

### R-01 — Local write authorized by staging permission

- **Severity:** medium
- **File:** `skills/prelaunch-security-audit/scripts/execution_profiles.py`
- **Defect:** `assess()` blocked `authorized-staging` + `verify_local`, but a
  `modify_local` request under `authorized-staging` could reach
  `eligible_for_host_dispatch` with a valid authorization reference. Staging
  permission must never authorize a local filesystem write, and `modify_local`
  needs the same isolation controls as local execution.
- **Fix:** block both `verify_local` and `modify_local` under
  `authorized-staging`; require `isolated-local` plus a non-empty
  `isolation_ref` and all seven enforced controls for `modify_local`.
- **Regression test:** `test_static_and_staging_cannot_execute_local_code`
  (extended) and `test_local_write_needs_full_isolation_controls`.
- **Observed after fix:** staging + write returns `blocked`; isolated-local +
  write with one control missing returns `not_verified`; with all controls
  returns `eligible_for_host_dispatch`. `StaticHost` still denies writes.

### R-02 — Failed executed coverage could not downgrade an all-clear

- **Severity:** high (reporting integrity)
- **File:** `skills/prelaunch-security-audit/scripts/render_report.py`
- **Defect:** `render()` downgraded a `no blockers found in tested scope`
  recommendation when coverage was partial, blocked, deferred or unassessed,
  but ignored a coverage evidence row with `result: "fail"`. A failed executed
  authorization test could therefore coexist with an all-clear.
- **Fix:** treat any executed coverage evidence with `result: "fail"` as
  incomplete, and print the count of failed executed checks.
- **Regression test:** `test_failed_executed_coverage_check_prevents_all_clear`.
- **Observed after fix:** recommendation renders as `CONDITIONAL LAUNCH` and
  reports `Executed checks recorded as failed: 1`.

### R-03 — Private evidence source could be swapped after check

- **Severity:** medium (local race / link following)
- **File:** `evals/seal_evidence.py`
- **Defect:** `_validate_private_source` checked `is_symlink()` / `is_file()`
  and then called `read_bytes()`. A local attacker able to swap the path could
  redirect the read. FIFOs were not explicitly rejected.
- **Fix:** open with `O_NOFOLLOW` and `O_NONBLOCK`, `fstat` the open descriptor,
  require a regular file, enforce the byte cap before and during a bounded read,
  and close the descriptor in `finally`.
- **Regression test:** `test_private_source_reader_never_follows_links_or_fifos`
  and the existing `test_refuses_symlink_review_record`.
- **Observed after fix:** symlink and FIFO inputs raise `ValueError`; a regular
  file of the allowed size returns its bytes; an over-limit read raises
  `ValueError`.

### R-04 — Report redaction missed common token formats

- **Severity:** low to medium (secret exposure in generated reports)
- **File:** `skills/prelaunch-security-audit/scripts/render_report.py`
- **Defect:** redaction covered GitHub and generic `sk-` tokens but not AWS
  access keys, Google API keys, Slack tokens, JWTs, Stripe live/test keys or
  `Bearer` credentials.
- **Fix:** add bounded patterns for those formats and keep the existing
  `[REDACTED]` replacement.
- **Regression test:** `test_secret_redacted_and_pipes_escaped` (extended with
  seven concrete synthetic samples).
- **Observed after fix:** each sample is replaced and the sanitized string still
  escapes pipes and HTML.
- **Residual risk:** pattern redaction is best-effort and cannot guarantee
  removal of every secret, especially novel or split formats.

### R-05 — Portability repair required a user-writable symlink guard

- **Severity:** medium (control added during repair; the baseline failed closed)
- **Files:** `skills/prelaunch-security-audit/scripts/audit_artifacts.py`,
  `skills/prelaunch-security-audit/scripts/execution_profiles.py`
- **Defect:** the portable fix required canonicalizing system symlinks, but a
  naive `realpath()` would also follow user-controlled links. The artifact root
  must not be redirectable by repository or task data. This was a hazard in the
  repair design, not an exploitable baseline behavior: the baseline rejected all
  symlink roots, including macOS `/var`.
- **Fix:** `trusted_root()` walks the operator root and permits only links whose
  parent cannot be modified by the current user and whose link owner is root
  (immutable system links such as macOS `/var`). All other symlink components
  are rejected. `read_artifact`, `write_new_artifact` and `StaticHost` use it;
  relative path components below the root are still opened with `O_NOFOLLOW`.
- **Regression tests:** `test_immutable_system_root_symlink_is_canonicalized`,
  `test_user_writable_symlink_root_rejected`,
  `test_output_symlink_parent_and_leaf_never_modify_target`,
  `test_artifact_root_parent_link_rejected`.
- **Observed after fix:** macOS temporary roots work; a user-created directory
  symlink is rejected; output symlink parent/leaf writes fail without touching
  the target.
- **Residual risk:** `trusted_root` trusts the operator-supplied root. It does
  not bind that root to a Git revision; the host must do that separately.

## 4. What the regression tests do and do not prove

They prove the five code paths now reject the specific synthetic inputs above.
They do not prove:

- that a real host enforces `assess()` or `HostAttestation`;
- that the Skill is safe against arbitrary target code;
- that redaction removes every real secret;
- that the fixed code is free of other defects;
- that the fixes improve vulnerability detection in real repositories.

The separate-context AI review was commissioned against the frozen fix revision
to look for additional bypasses. Its findings and disposition are recorded in
`docs/security/v0.5.0-independent-review.md` and
`docs/security/v0.5.0-findings.json`. Because that reviewer is an AI system with
no independent human accountability, it cannot satisfy the release requirement
for independent security review.

R-04), add one boundary control required by the macOS portability repair (R-05),
