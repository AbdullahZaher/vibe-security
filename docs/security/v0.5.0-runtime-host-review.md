## 1. What the Skill and Host Adapter actually enforce

`prelaunch-security-audit` v0.5.0 provides three runtime components:

1. `execution_profiles.assess()`, which classifies proposed actions and returns
   `blocked`, `not_verified` or `eligible_for_host_dispatch`. It never executes.
   Eligibility requires a trusted `HostAttestation` callback supplied by the
   embedding host. For `verify_local` and `modify_local`, `HostAttestation` strictly
   requires both `command_sha256` and `spec_sha256` binding the immutable `ExecutionSpec` (A2, R-07).
   Missing, mismatched, or forged attestations fail closed immediately.
2. `execution_profiles.StaticHost`, a deny-only in-process broker that permits
   allowlisted, bounded regular-file reads and denies network, writes, local
   execution and destructive effects.
3. `runtime_host_adapter.IsolatedHostAdapter`, a hardened host adapter integrating
   with `assess()`, `HostAttestation`, and an immutable `ExecutionSpec`. It executes
   authorized local tests inside a technically enforced sandbox (macOS Seatbelt) with:
   - Genuine **default-deny** filesystem read policy (`(deny default)` + `(import "system.sb")`)
     denying `/etc/passwd`, `/etc/master.passwd`, host user directories (`/Users`),
     home directory, external volumes (`/Volumes`), temporary trees, and all unallowlisted paths,
     allowing only system libraries, Python interpreter dependencies, read-only `source_root`,
     and writable `scratch_root` (R-01, R-05);
   - Fail-closed guard rejecting execution if `sys.prefix` or `sys.base_prefix` equals the user
     home directory (R-05);
   - Read-only source access and writable disposable scratch space;
   - Cryptographic and structural binding of the executed command vector to the
     authorized request, blocking substitution before process creation (R-02);
   - Thread-locked and file-locked (`fcntl.flock`) `ApprovalStore` with persistent default backing
     (`~/.vibe-security/approvals.json`) preventing duplicate execution or cross-process replay of
     previously consumed approvals, with fail-closed corruption handling and strict `0o600` file permissions (A1, R-02, R-07);
   - Mandatory construction of `ExecutionSpec` *before* authorization request and binding of `spec_sha256`
     into both request and attestation (A2, R-07);
   - Telemetry sanitization in `adapter.events` retaining executable name, argument count,
     and SHA-256 digest while redacting raw command argument strings to prevent credential leaks (R-07);
   - Unconditional network egress denial (`(deny network*)`) and fail-closed dispatch for remote effects (R-03);
   - Incremental bounded streaming collection of stdout and stderr up to `max_bytes`,
     immediately terminating the spawned process group via `SIGKILL` on excess output (R-04);
   - Process group isolation (`start_new_session=True`, `close_fds=True`) and unconditional
     session process-group termination (`os.killpg(saved_pgid, signal.SIGKILL)`) in `finally`,
     guaranteeing that all descendant/grandchild processes within the process group are terminated
     even if the direct child exits first or descendants close inherited pipes (A3, R-04, R-06);
   - Credential scrubbing and `PYTHONNOUSERSITE=1` enforcement.

## 2. Reference host profile

The hardened `IsolatedHostAdapter._make_seatbelt_profile()` applies a genuine default-deny policy:

```scheme
(version 1)
(deny default)
(import "system.sb")

;; Explicit credential denial overriding system.sb
(deny file-read* (literal "/private/etc/master.passwd"))
(deny file-read* (literal "/etc/master.passwd"))
(deny file-read* (literal "/private/etc/passwd"))
(deny file-read* (literal "/etc/passwd"))

;; Unconditional network and write denial
(deny network*)
(deny file-write*)
(allow file-write* (subpath "<scratch>"))

;; Execution and runtime primitives
(allow process-exec)
(allow process-fork)
(allow sysctl-read)
(allow signal (target self))
(allow file-read-metadata)
(allow file-read* (subpath "/dev"))

;; Allowlisted interpreter dependencies and authorized roots

(allow file-read* (subpath "<sys.base_prefix>"))
```

## 4. Authorization boundaries

The controller and adapter distinguish the documented effects:

- `observe` / `read_source` under `static-only`: eligible only with a trusted
  host authorization for the exact request identity.
- `network_read`, `external_write`: direct arbitrary child process dispatch is
  strictly prohibited and fails closed.
- `modify_local`, `verify_local`: requires `isolated-local` profile, verified
  `HostAttestation` with all 7 controls, and exact command binding before dispatch.
- `destructive`: blocked unconditionally.
- Foreign target, foreign revision, wrong path, traversal, symlink, FIFO,
  oversized read, unapproved command substitution, and replay attempts are denied.

## 6. Network isolation

Target-controlled code execution inside the sandbox has `(deny network*)` enforced
unconditionally. In addition, `dispatch()` rejects any request with network side effects
(`network_read`, `external_write`) because OS-level Seatbelt cannot guarantee Layer 7
destination-level egress filtering.

## 7. Process and resource limits

- `start_new_session=True` runs child processes in an isolated session/process group.
- `close_fds=True` prevents host file-descriptor inheritance.
- `_run_bounded_process` reads stdout and stderr in 4 KB chunks and terminates the
  entire process group with `os.killpg(pgid, signal.SIGKILL)` as soon as `max_bytes`
  is exceeded, preventing unbounded buffering in memory (R-04).
- Timeouts terminate the process group via `SIGKILL` within finite wall-clock limits,
  preventing orphaned processes (R-04).
- In addition, `_run_bounded_process` unconditionally executes `os.killpg(saved_pgid, signal.SIGKILL)`
  in a `finally:` block and reaps the direct child via `proc.wait(timeout=1)`, guaranteeing
  that all descendant and grandchild processes remaining within the session process group
  are terminated when the bounded process exits (A3, R-06).
- **POSIX Boundary Limitation (A3):** While process group cleanup terminates all normal descendants,
  if an untrusted child double-forks and invokes `os.setsid()`, it establishes a new session ID and
  process group. Darwin's Seatbelt mechanism does not intercept or prevent `setsid()`. Consequently,
  POSIX `killpg(saved_pgid)` cannot reach detached sessions. Complete process containment against
  deliberate `setsid()` daemonization cannot be guaranteed on developer hosts without Linux PID namespaces/cgroups
  or virtual machines.
- CPU time limits are applied via `RLIMIT_CPU` in `preexec_fn`.

## 8. Evidence authenticity and telemetry integrity

The adapter records exact `spec_sha256`, `request_sha256`, `exit_code`, `timed_out`,
`wall_ms`, `stdout_sha256`, `stderr_sha256`, and `output_truncated` in `adapter.events`.
In `event["spec"]`, command arguments are sanitized to retain `executable`, `command_sha256`,
and `command_arg_count`, redacting raw command argument strings from host telemetry to
prevent secret leakage while maintaining 100% cryptographic auditability (R-07).
All telemetry is retained by the trusted host outside the target.

## 9. What remains unsupported

- No Linux or Windows in-kernel isolation adapter verified in CI (Seatbelt probe is macOS-specific).
- No kernel-level process namespace or cgroup isolation against `setsid()` session escape on macOS Darwin (A3).
- No production container, VM, microVM or multi-tenant agent worker isolation.
- No external-egress, DNS filtering or authenticated proxy gateway test.
- No testing against real customer repositories or production infrastructure.

## 10. Residual risk and release decision

`IsolatedHostAdapter` on macOS has verified technical boundaries for local verification tasks.
On non-macOS platforms or without `/usr/bin/sandbox-exec`, it safely fails closed (`blocked=True`),
preserving `static-only` analysis as the authorized fallback.

Until multi-tenant container or VM isolation is deployed for external execution,
arbitrary-code execution on production multi-tenant servers remains outside the verified scope.
For local single-developer auditing on macOS with explicit owner authorization,
**runtime hardening is verified** (`runtime_hardening_verified`).
