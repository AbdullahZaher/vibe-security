## 1. What the Skill actually enforces

`prelaunch-security-audit` v0.5.0 ships two relevant controller components:

1. `execution_profiles.assess()`, which classifies a proposed action and returns
   `blocked`, `not_verified` or `eligible_for_host_dispatch`. It never executes.
   Eligibility requires a trusted `HostAttestation` callback supplied by the
   embedding host, never by JSON.
2. `execution_profiles.StaticHost`, a deny-only in-process broker that permits
   allowlisted, bounded regular-file reads and denies network, writes, local
   execution and destructive effects.

Neither component is an operating-system sandbox. `StaticHost` has no process,
network or write dispatcher. A host that executes target code must supply its own
verified isolation adapter; the Skill deliberately does not bundle one.

The probe therefore separates:

- **controller checks** — actual Skill code (`StaticHost`, `assess`,
  `bounded_command`);
- **host-platform checks** — a reviewed Seatbelt profile applied by macOS
  `sandbox-exec`, demonstrating what a host adapter can enforce.

## 2. Reference host profile

The probe creates synthetic fixtures under a disposable directory and applies:

```scheme
(version 1)
(allow default)
(deny network*)
(deny file-write*)
(allow file-write* (subpath "<scratch>"))
(deny file-read* (subpath "<synthetic-secret>"))
```

The subprocess check adds `(deny process-fork)`. The profile is intentionally
simple: it tests the boundary mechanism, not a production host configuration.

## 4. Authorization boundaries

The controller distinguishes the documented effects:

- `observe` / `read_source` under `static-only`: eligible only with a trusted
  host authorization for the exact request identity.
- `network_read`, `external_write`, `modify_local`, `verify_local`,
  `destructive`: denied by `StaticHost`; `assess` blocks destructive effects,
  blocks all non-observe effects under `static-only`, blocks local writes and
  local execution under `authorized-staging`, and requires an isolation
  attestation with all seven controls for local execution or local writes under
  `isolated-local`.
- Foreign target, foreign revision, wrong path, traversal, symlink, FIFO,
  oversized read and non-read operations are denied.

These are controller decisions, not proof that another host enforces them. A
host that ignores `assess()` can still execute the action.

## 5. Filesystem isolation

Observed on the disposable host profile:

- fixture source readable;
- scratch writable;
- fixture, parent workspace and synthetic secret non-writable/non-readable;
- a symlink inside the writable scratch directory pointing at the synthetic
  secret could not be followed;
- no unexpected file appeared in the fixture or other workspace;
- the probe removed its temporary fixture directory; no `v050-boundary-*`
  directory remained after the run.

The Skill's own `trusted_root` and descriptor-relative reads were separately
tested: user-writable symlink roots are rejected, immutable system links such as
macOS `/var` are canonicalized, and relative artifact components are never
followed. This is an artifact-boundary control, not OS process isolation.

## 6. Network isolation

Only loopback was tested. The sandboxed client could not connect to a listener
that was reachable without the sandbox. No attempt was made to contact an
external service. This verifies the Seatbelt `network*` denial mechanism on this
host, not a general egress policy, DNS control or proxy enforcement.

## 7. Process and resource limits

- `process-fork` denial blocked a Python `subprocess.run` with
  `PermissionError`.
- `ulimit -t 1` terminated a busy loop with `SIGXCPU` (exit `-24`) after about
  one second.
- The controller's bounded output reader rejected a 5,000-byte child at a
  100-byte cap.
- No memory, disk-quota, process-count, wall-clock or artifact-size limit was
  enforced by the probe. Those remain host responsibilities.

## 8. Evidence authenticity

The probe records actual child exit codes, signal numbers, stdout/stderr byte
counts and a SHA-256 of stderr. The denial marker is computed from real stderr
text. No mocked process, fake client or simulated tool response is used. The raw
report is `0600` and stored outside the repository.

This does **not** authenticate model output, host attestations or retained
evidence. It proves only what this probe executed on this host.

## 9. What remains unsupported

- No Skill-bundled arbitrary-code runner.
- No validated host adapter that consumes `HostAttestation` and enforces the
  seven controls at dispatch.
- No container, VM, microVM or separate-user isolation test.
- No memory/disk/process-count quota test.
- No external-egress, DNS or proxy-bypass test.
- No MCP host or tool-schema attack test.
- No cleanup verification after a hard kill or host crash.
- No test against a real target repository or real credentials.

## 10. Residual risk

A host can misconfigure the profile, ignore `assess()`, reuse an approval, expose
a secret through a mount, or run target code without the required controls.
`sandbox-exec` is a deprecated platform facility and profiles are easy to
over-permit. `StaticHost` is a deny-only broker, not a sandbox. Until an
independently reviewed adapter enforces the controls at dispatch and its logs are
retained outside the target, runtime execution of untrusted repository code
remains **not authorized**.
