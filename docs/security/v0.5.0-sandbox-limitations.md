# v0.5.0 sandbox and runtime limitations

This document states what the v0.5.0 Skill and its probe do **not** guarantee.
It exists to prevent unit tests, a deny-only broker or a single macOS profile
from being mistaken for arbitrary-code isolation.

## 1. No bundled arbitrary-code sandbox

`prelaunch-security-audit` ships no container, VM, microVM, seccomp profile,
user-namespace wrapper, cgroup policy or OS sandbox launcher.

- `execution_profiles.assess()` is a classifier. It returns `blocked`,
  `not_verified` or `eligible_for_host_dispatch`. It never executes and cannot
  prevent a host from ignoring its result.
- `execution_profiles.StaticHost` is an in-process, deny-only broker for
  allowlisted regular-file reads. It has no network, write, process or package
  execution dispatcher.
- `plan_guard.py` is advisory. It classifies a proposed plan; it does not grant
  permission or run anything.

A host that wants to execute target code must integrate an independently
reviewed adapter, verify the seven controls at dispatch, enforce an exact action
approval and retain logs outside the target.

## 2. What was verified on this host

The macOS probe demonstrates that the platform *can* enforce:

- read-only fixture source and writable scratch separation;
- denial of writes to the target, parent workspace and another workspace;
- denial of reads from a synthetic host secret;
- denial of a symlink escape from writable scratch to the secret;
- denial of loopback network connections;
- denial of process forking;
- CPU-time termination with `SIGXCPU`;
- controller-level bounded child output.

It does not demonstrate that the Skill enforces these controls by itself.

## 3. What was not verified

- **Memory:** no address-space or RSS limit was tested.
- **Disk:** no quota, inode or artifact-size limit was enforced at the OS layer.
- **Process count:** only a single fork denial was tested.
- **Wall clock:** no host-level watchdog killed a hung process; only CPU time
  and the probe timeout were exercised.
- **External egress:** only loopback was tested. DNS, HTTP proxies, IPv6,
  alternate protocols and raw sockets were not tested.
- **Containers/VMs:** no Docker, Podman, VM, microVM or separate-user boundary
  was tested. Docker alone is not assumed sufficient.
- **MCP:** no real MCP server, tool-schema attack, cross-server call or token
  passthrough was tested.
- **Host adapter:** no adapter that consumes `HostAttestation` and enforces
  controls at dispatch exists or was reviewed.
- **Evidence authenticity:** retained logs, attestations and model output are
  not cryptographically authenticated by the Skill.
- **Cleanup:** successful probe cleanup was observed, but cleanup after
  `SIGKILL`, host crash or power loss was not.
- **Real targets:** no real repository, credential, production socket, Docker
  daemon or customer data was used.

## 4. Platform limitations

- `sandbox-exec` is deprecated on macOS. Profiles can over-permit, and the
  facility may change or disappear.
- The probe profile uses `(allow default)` plus specific denials. A production
  profile should use default-deny and an explicit allowlist, which requires more
  platform knowledge and testing.
- Seatbelt path rules interact with symlinks and canonical paths. The probe
  canonicalizes its fixture root, but other hosts may not.
- macOS resource limits differ from Linux cgroups/seccomp. A macOS result is not
  a Linux guarantee, and vice versa.
- A sandbox that blocks `process-fork` may still allow in-process code to consume
  CPU, memory or file descriptors until a separate limit applies.

## 5. Skill-boundary limitations

- `trusted_root` canonicalizes immutable system symlinks but trusts the
  operator-supplied root. If the operator points it at the wrong directory, the
  artifact boundary is wrong.
- `StaticHost` binds a request to a target string and revision string. It does
  not verify that the root matches a Git commit; the host must bind copied
  artifacts to the frozen source separately.
- Report redaction is best-effort. It now covers common token formats, but no
  pattern set can guarantee removal of every secret.
- The live runner verifies tracked checkout cleanliness and captured bytes
  against HEAD. It does not prove model identity, provider behavior, reviewer
  independence or ground truth.
- `evaluate_trial_matrix.py` refuses to mark release review ready without a
  trusted host callback. The CLI has no such callback by design.

## 6. Safe operating rule

Until an independently reviewed runtime adapter and host attestation channel
exist:

1. default to `static-only`;
2. do not execute package scripts, Git hooks, test discovery imports, containers
   or downloaded tools from the target;
3. do not send target source to a model provider without written authorization;
4. record unexecuted checks as **Authorized next checks (not executed)**;
5. keep evidence outside the target and outside public Git;
6. treat a model statement that it did not execute something as a claim, never as
   proof.
