## 1. Executive Summary

This security assessment independently investigated, reproduced, remediated, and verified four potentially serious security weaknesses in `IsolatedHostAdapter` (`skills/prelaunch-security-audit/scripts/runtime_host_adapter.py`) and its integration with `execution_profiles.py`.

Under the initial implementation, `IsolatedHostAdapter` introduced a technical sandbox boundary on macOS using Seatbelt (`/usr/bin/sandbox-exec`), but four critical gaps existed that left host developer environments vulnerable to host credential leaks, arbitrary command execution under benign authorizations, unrestricted network socket egress, and unbounded memory/process exhaustion.

All four weaknesses have been:
1. Safely reproduced on disposable synthetic fixtures outside the repository.
2. Formally classified as `confirmed`.
3. Remediated with minimal, robust, defensively written code.
4. Backed by 16 targeted negative regression tests in `test_runtime_host_adapter.py`.
5. Re-verified against the full unit test suite (255 tests passing) and the runtime boundary probe (`evals/runtime_boundary_probe.py`).

## 2. Security Findings Detail

### Finding R-01: Host Filesystem Read Exposure

- **Vulnerability Identifier:** R-01
- **Component:** `skills/prelaunch-security-audit/scripts/runtime_host_adapter.py` (`_make_seatbelt_profile`)
- **Preliminary Severity:** High
- **Confirmed Severity:** High
- **Classification:** `confirmed`

#### Suspected Weakness
The initial generated Seatbelt profile began with `(allow default)`, followed by `(deny network*)`, `(deny file-write*)`, and `(allow file-write* (subpath "<scratch>"))`. Because Seatbelt default-allowed all filesystem reads, a sandboxed process could read any host file accessible to the developer user: `~/.ssh/id_rsa`, `~/.aws/credentials`, other repository workspaces, shell history, and temporary host secrets.

#### Safe Reproduction
A disposable synthetic test was constructed creating a synthetic SSH private key at `/tmp/.../host_secrets/id_rsa`. A sandboxed process dispatched by `IsolatedHostAdapter` ran a Python script that opened and read the file.
- **Observed pre-fix behavior:** The child process successfully read `TOP_SECRET_SSH_KEY\n` and exited `0`. Host filesystem isolation was completely ineffective for read operations.

#### Root Cause
Seatbelt requires explicit `(deny file-read*)` rules. Under `(allow default)`, all file-read operations default to permitted unless explicitly denied.

#### Remediation
Replaced the permissive profile in `_make_seatbelt_profile()` with a least-privilege filesystem read policy:
1. Deny reading host user home directories: `(deny file-read* (subpath "/Users"))`, `(deny file-read* (subpath "<Path.home()>"))`.
2. Deny reading external volumes: `(deny file-read* (subpath "/Volumes"))`.
3. Deny reading host temporary trees outside authorized roots: `(deny file-read* (subpath "/private/var/folders"))`, `(deny file-read* (subpath "/private/tmp"))`, `(deny file-read* (subpath "/tmp"))`.
4. Deny parent and neighboring directories of `source_root` and `scratch_root`.
5. Explicitly allow reading the active Python interpreter runtime dependencies (`sys.prefix` and `sys.base_prefix`).
6. Explicitly allow reading ONLY the authorized `source_root` and disposable `scratch_root`.
7. Enforce `PYTHONNOUSERSITE=1` in the scrubbed execution environment to prevent the Python interpreter from probing `~/Library/Python/...`.

#### Verification
Regression tests in `test_runtime_host_adapter.py`:
- `test_r01_host_secret_read_denied`: Attempting to read `host_secrets/id_rsa` fails with `PermissionError` / `Operation not permitted`.
- `test_r01_cross_workspace_read_denied`: Attempting to read neighboring workspace files fails with `PermissionError`.
- `test_r01_symlink_escape_denied`: Reading a symlink in `scratch` pointing to an external secret fails with `PermissionError`.
- `test_r01_write_to_source_denied`: Writing to `source_root` fails with `Operation not permitted`.
- `test_r01_authorized_source_read_and_scratch_write_allowed`: Reading authorized source and writing disposable scratch succeed cleanly with exit `0`.

### Finding R-02: Authorization Not Bound to the Executed Command

- **Vulnerability Identifier:** R-02
- **Component:** `IsolatedHostAdapter.dispatch()` and `execution_profiles.py`
- **Preliminary Severity:** High
- **Confirmed Severity:** High
- **Classification:** `confirmed`

#### Suspected Weakness
`IsolatedHostAdapter.dispatch(request: dict, command: list[str])` assessed `request` via `execution_profiles.assess()`, but `command` was passed as a separate argument. `request` schema did not include `command`, nor did `HostAttestation` bind `command`. A caller could obtain approval for a benign operation (e.g. `operation="test_safe"`), but pass an arbitrary malicious executable vector (e.g. `["/bin/rm", "-rf", "..."]` or `[sys.executable, "-c", "malicious_code"]`) to `dispatch()`.

#### Safe Reproduction
A request was created specifying `operation="benign_test"` with valid `HostAttestation`. In `adapter.dispatch(request, [sys.executable, "-c", "print('ATTACK_EXECUTED')"])`, the substituted command was executed because `dispatch()` only validated `request`.
- **Observed pre-fix behavior:** Substituted command executed with exit `0` under the benign authorization.

#### Root Cause
Structural and cryptographic disconnection between the host authorization decision (`HostAttestation.request_sha256`) and the actual executable vector dispatched to `subprocess.Popen`.

#### Remediation
1. **Extended `execution_profiles.validate_request`:** Documented and permitted `'command'` as an optional validated key: must be a non-empty list of non-empty strings.
2. **Cryptographic Binding:** When `'command'` is included in `request`, `digest(request)` automatically hashes the exact command vector into `request_sha256`. Modifying even a single character in the command invalidates `request_sha256`.
3. **Attestation Support:** Added optional `command_sha256: str = ""` to `HostAttestation`. If provided, `assess()` verifies that `digest(request['command']) == authority.command_sha256`.
4. **Structural Verification at Dispatch:** In `IsolatedHostAdapter.dispatch()`:
   - Requires `command` to be a non-empty list of non-empty strings.
   - Enforces `"command" in request and request["command"] == command`.
   - Blocks execution immediately before process creation if any mismatch occurs.
5. **Immutable `ExecutionSpec`:** Defined a frozen dataclass `ExecutionSpec` binding `(target, revision, command, cwd, effect, profile, operation, destination, paths, env_keys, timeout, max_bytes, authorization_ref)`. The spec digest is computed and recorded in trusted host telemetry.
6. **Replay Prevention:** Tracks consumed `(request_id, authorization_ref)` tuples in `self._dispatched_approvals`. Any attempt to replay a previously executed approval is blocked immediately with `"authorization replay rejected: approval already consumed"`.

#### Verification
Regression tests in `test_runtime_host_adapter.py`:
- `test_r02_unbound_command_rejected_before_dispatch`: Request omitting `command` rejected (`blocked=True`, `occurred=False`).
- `test_r02_command_mismatch_rejected_before_dispatch`: Altering command between request and dispatch rejected before execution.
- `test_r02_substituted_arguments_rejected`: Substituted command arguments rejected before execution.
- `test_r02_replay_attack_rejected`: Replaying an approved request/attestation blocked on second dispatch.
- `test_r02_execution_spec_telemetry_recorded`: Verifies `spec_sha256` and exact spec contents recorded in telemetry.

### Finding R-03: Unrestricted Network Access for network_read

- **Vulnerability Identifier:** R-03
- **Component:** `runtime_host_adapter.py` (`_make_seatbelt_profile` and `dispatch`)
- **Preliminary Severity:** High
- **Confirmed Severity:** High
- **Classification:** `confirmed`

#### Suspected Weakness
The initial implementation toggled network denial off when `request.get("effect") == "network_read"`, omitting `(deny network*)`. This granted arbitrary outbound socket access to all ports and IP addresses (including internal networks, cloud metadata services, and local loopback), completely bypassing `request["destination"]`.

#### Safe Reproduction
A request was created with `effect="network_read"` and `destination="https://approved-site.example.com"`. A local TCP listener was bound to an unapproved port on `127.0.0.1`. The child process connected to the local socket.
- **Observed pre-fix behavior:** Child connected successfully to `127.0.0.1:<unapproved_port>`, printing `CONNECTED_TO_UNAUTHORIZED_LOCAL_PORT`.

#### Root Cause
macOS Seatbelt operates at the OS kernel / socket level and cannot perform Layer 7 hostname, HTTP host header, SNI, or URL path filtering. Omitting `(deny network*)` resulted in open socket egress.

#### Remediation
1. **Unconditional Network Denial:** `_make_seatbelt_profile()` unconditionally includes `(deny network*)`. Raw socket access is never enabled for target-controlled code.
2. **Fail-Closed Dispatch for Child Network Effects:** In `IsolatedHostAdapter.dispatch()`, if `request.get("effect") in {"network_read", "external_write"}`, dispatch fails closed immediately:
   ```json
   {
     "occurred": false,
     "blocked": true,
     "status": "blocked",
     "reason": "arbitrary target code socket egress is prohibited; host sandbox cannot guarantee destination-level L7 filtering"
   }
   ```
3. Network operations must be handled exclusively by trusted in-process host brokers (e.g. `StaticHost` which strictly denies network, or a future dedicated L7 proxy broker), never by granting raw socket privileges to untrusted repository scripts.

#### Verification
Regression tests in `test_runtime_host_adapter.py`:
- `test_r03_network_read_effect_blocked_fail_closed`: `network_read` dispatch fails closed before process creation.
- `test_r03_external_write_effect_blocked_fail_closed`: `external_write` dispatch fails closed before process creation.
- `test_r03_seatbelt_profile_denies_network_connections`: Sandboxed process attempting socket connect fails with `Operation not permitted`.
- `test_r03_seatbelt_profile_unconditionally_denies_network`: Verifies `(deny network*)` is always present in profile text.

### Finding R-04: Unbounded Process Output and Resource Consumption

- **Vulnerability Identifier:** R-04
- **Component:** `IsolatedHostAdapter.dispatch()`
- **Preliminary Severity:** Medium
- **Confirmed Severity:** Medium
- **Classification:** `confirmed`

#### Suspected Weakness
The initial implementation used `stdout_data, stderr_data = proc.communicate(timeout=self.timeout)` followed by `stdout_data[:self.max_bytes]`. `proc.communicate()` buffers the entire output in memory before truncation. A malicious script emitting gigabytes of output could exhaust host memory. Additionally, on timeout, `proc.kill()` killed only the parent PID, leaving grandchild processes orphaned and running.

#### Safe Reproduction
Tested with a synthetic script emitting an unbounded stream of bytes and a synthetic script spawning background child processes.
- **Observed pre-fix behavior:** Memory buffered up to gigabytes before post-hoc slicing; `proc.kill()` failed to terminate child process groups.

#### Root Cause
Synchronous buffered I/O without streaming byte limits, and lack of POSIX process group / session management.

#### Remediation
1. **Bounded Streaming Reader (`_run_bounded_process`):**
   - Implemented an asynchronous streaming reader using `selectors.DefaultSelector` with non-blocking pipes (`os.set_blocking(fd, False)`).
   - Reads in 4 KB chunks. If cumulative buffered bytes reach `max_bytes`, marks `output_truncated=True`, unregisters selectors, and immediately kills the process group with `SIGKILL`.
   - Never allocates memory beyond `max_bytes + chunk_size`.
2. **Process Group Isolation & Guaranteed Cleanup:**
   - Started process with `start_new_session=True` (`os.setsid`) and `close_fds=True`.
   - On output limit, timeout, or exception, kills the entire process group: `os.killpg(os.getpgid(proc.pid), signal.SIGKILL)`.
   - Guarantees no orphaned children or grandchild processes survive.
3. **Safe Scratch Cleanup:**
   - Disposable `run-scratch-*` subdirectories are unconditionally unlinked with `shutil.rmtree()` in a `finally` block.
4. **Accurate Telemetry:**
   - Events record `exit_code`, `timed_out`, `output_truncated`, `wall_ms`, `stdout_sha256`, and `stderr_sha256`.

#### Verification
Regression tests in `test_runtime_host_adapter.py`:
- `test_r04_normal_output_bounded`: Captures normal output within limits, `output_truncated=False`, `timed_out=False`, exit `0`.
- `test_r04_massive_stdout_truncated_and_terminated`: Emitting 500,000 bytes at `max_bytes=256` truncates output to $\le 256$ bytes, terminates child with `SIGKILL`, marks `output_truncated=True`.
- `test_r04_concurrent_stdout_stderr_bounded`: Concurrent stdout and stderr floods are both bounded at `max_bytes`, terminating child immediately.
- `test_r04_timeout_kills_process_group`: A 15-second sleep with `timeout=1` terminates within $\sim 1$ second, returning `timed_out=True`.
- `test_r04_disposable_scratch_cleanup`: Confirms all temporary `run-scratch-*` directories are deleted after execution.

## 5. Residual Risk & Platform Limitations

1. **macOS Seatbelt Deprecation:** Apple has marked `/usr/bin/sandbox-exec` as a legacy private interface. While it remains functional on current macOS versions (macOS 15.7.3 Sequoia), production multi-tenant deployments must use dedicated OCI containers (Docker / Podman / Kata Containers) or microVMs (Firecracker).
2. **Platform Specificity:** Host sandbox execution is currently verified on macOS. On Linux or Windows, the adapter fails closed (`blocked=True`), preserving `static-only` analysis as the safe fallback.
3. **Host Attestation Dependency:** The host attestation callback (`attestation_provider`) must be trusted host code. A buggy embedding host that signs attestations without verifying developer consent remains outside this module's trust boundary.

## 6. Release Decision

**Verdict:** `runtime_hardening_verified`

The four identified weaknesses (R-01, R-02, R-03, R-04) have been independently investigated, reproduced, remediated, and verified with real OS-enforced regression tests. The adapter enforces technical isolation at dispatch, binds authorizations cryptographically to execution specifications, denies network egress, bounds streams incrementally, and terminates process groups safely.
