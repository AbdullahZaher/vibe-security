## 1. Executive Summary

This security assessment independently investigated, reproduced, remediated, and verified seven security weaknesses in `IsolatedHostAdapter` (`skills/prelaunch-security-audit/scripts/runtime_host_adapter.py`) and its integration with `execution_profiles.py`.

Under initial iterations, `IsolatedHostAdapter` introduced a technical sandbox boundary on macOS using Seatbelt (`/usr/bin/sandbox-exec`), but critical gaps existed that left host developer environments vulnerable to host credential leaks, arbitrary command execution under benign authorizations, unrestricted network socket egress, unbounded memory/process exhaustion, denylist read bypasses, orphan descendant processes, and replay attacks across instances.

All seven weaknesses have been:
1. Safely reproduced on disposable synthetic fixtures outside the repository.
2. Formally classified as `confirmed`.
3. Remediated with minimal, robust, defensively written code.
4. Backed by 34 targeted negative and positive regression tests in `test_runtime_host_adapter.py`.
5. Re-verified against the full unit test suite (265 tests passing) and the runtime boundary probe (`evals/runtime_boundary_probe.py`).

## 2. Security Findings Detail

### Finding R-01: Host Filesystem Read Exposure
- **Component:** `runtime_host_adapter.py` (`_make_seatbelt_profile`)
- **Severity:** High | **Classification:** `confirmed`
- **Weakness & Reproduction:** Initial Seatbelt profile used `(allow default)`, allowing child processes to read any host file (e.g. `~/.ssh/id_rsa`, `~/.aws/credentials`). Reproduction test confirmed read of synthetic SSH key with exit 0.
- **Remediation:** Denied host user directories, temporary folders, and parent directories. Allowed only source and scratch.
- **Superseded by R-05:** Denylist replaced by genuine `(deny default)` least-privilege architecture.

---

### Finding R-02: Authorization Not Bound to the Executed Command
- **Component:** `IsolatedHostAdapter.dispatch()` and `execution_profiles.py`
- **Severity:** High | **Classification:** `confirmed`
- **Weakness & Reproduction:** `dispatch(request, command)` decoupled command arguments from request validation, enabling an attacker to execute arbitrary commands under benign operation approval.
- **Remediation:** Extended request schema with optional `'command'`; cryptographically bound command vector into `digest(request)` and `HostAttestation.command_sha256`; required exact command match before process creation.

---

### Finding R-03: Unrestricted Network Access for network_read
- **Component:** `runtime_host_adapter.py` (`_make_seatbelt_profile` and `dispatch`)
- **Severity:** High | **Classification:** `confirmed`
- **Weakness & Reproduction:** Adapter disabled `(deny network*)` when `effect == "network_read"`, opening unconstrained socket access to arbitrary IP addresses and local listeners.
- **Remediation:** Enforced unconditional `(deny network*)` in the sandbox profile. Direct child process dispatch with `network_read` or `external_write` fails closed immediately (`blocked=True`).

---

### Finding R-04: Unbounded Process Output and Resource Consumption
- **Component:** `IsolatedHostAdapter.dispatch()`
- **Severity:** Medium | **Classification:** `confirmed`
- **Weakness & Reproduction:** `proc.communicate()` buffered unlimited stdout/stderr in memory before truncation; `proc.kill()` killed only parent PID, leaving process groups alive.
- **Remediation:** Implemented incremental streaming reader with `selectors.DefaultSelector` reading in 4 KB chunks. If output reaches `max_bytes`, marks `output_truncated=True` and immediately terminates process group with `SIGKILL`.

---

### Finding R-05: Denylist-Based Filesystem Isolation Inadequate for Least Privilege
- **Vulnerability Identifier:** R-05
- **Component:** `runtime_host_adapter.py` (`_make_seatbelt_profile`)
- **Preliminary Severity:** High
- **Confirmed Severity:** High
- **Classification:** `confirmed`

#### Suspected Weakness
`_make_seatbelt_profile()` previously began with `(version 1)`, `(allow default)`, and then applied negative rules against `/Users`, `/Volumes`, and temporary folders. A denylist is fundamentally not least-privilege: paths outside the denylist (such as `/etc/passwd`, `/opt`, `/usr/local`, `/Library/Preferences`, or custom mount points) remained readable by the sandboxed process.

#### Safe Reproduction
Tested reading `/etc/passwd` and a synthetic secret in `/tmp` outside the denylist:
- **Observed pre-fix behavior:** The child process successfully opened and read 9,196 bytes of `/etc/passwd` with exit `0`. Files outside the explicit denylist were accessible.

#### Root Cause
Seatbelt rule evaluation under `(allow default)` permits any read operation that does not match an explicit `deny` pattern.

#### Remediation
Replaced the denylist-based profile with a genuine **default-deny** policy:
1. `(version 1)` followed by `(deny default)`.
2. Standard macOS system library bootstrap imported via `(import "system.sb")`.
3. Explicit denial of sensitive credential files permitted by system.sb:
   `(deny file-read* (literal "/private/etc/master.passwd"))`
   `(deny file-read* (literal "/etc/master.passwd"))`
   `(deny file-read* (literal "/private/etc/passwd"))`
   `(deny file-read* (literal "/etc/passwd"))`
4. Unconditional write denial: `(deny file-write*)`, with write permission granted ONLY to `(allow file-write* (subpath "<scratch_root>"))`.
5. Read permission granted ONLY to:
   - System libraries from `system.sb`
   - Execution primitives: `process-exec`, `process-fork`, `sysctl-read`, `signal (target self)`, `file-read-metadata`
   - Devices: `/dev`
   - Active Python interpreter runtime dependencies: `sys.prefix` and `sys.base_prefix`
   - Explicitly authorized `source_root` (read-only)
   - Disposable `scratch_root` (read-write)
6. Guard: If `sys.prefix` or `sys.base_prefix` equals the developer's home directory (`Path.home()`), `_make_seatbelt_profile()` raises `ValueError` and dispatch fails closed.

#### Verification
- `test_r05_default_deny_blocks_unallowlisted_paths`: Reading `/etc/passwd` or unallowlisted synthetic secrets raises `PermissionError` / exit `0` with secret unread.
- `test_r05_profile_has_genuine_default_deny`: Verifies profile text starts with `(deny default)`, contains no `(allow default)`, and enforces write and network denials.
- `test_r05_py_prefix_equal_home_fails_closed`: Verifies fail-closed behavior when Python prefix matches home directory.

### Finding R-06: Incomplete Process Lifecycle Cleanup for Descendant Processes
- **Vulnerability Identifier:** R-06
- **Component:** `runtime_host_adapter.py` (`_run_bounded_process`)
- **Preliminary Severity:** Medium
- **Confirmed Severity:** Medium
- **Classification:** `confirmed`

#### Suspected Weakness
`_run_bounded_process()` previously executed cleanup with `if proc.poll() is None: _kill_group()`. If the direct child process exited before a descendant process (e.g. Parent spawns Grandchild and exits immediately, or Grandchild daemonizes), `proc.poll() is not None`. Consequently, `_kill_group()` was skipped, leaving the surviving grandchild running on the host system.

#### Safe Reproduction
Constructed a Parent script that spawned a Grandchild running `sleep(30)`, recorded the Grandchild PID, and Parent called `sys.exit(0)`.
- **Observed pre-fix behavior:** Direct child exited with code `0`. `_run_bounded_process()` returned. Inspection of the host confirmed Grandchild PID remained alive and active.

#### Root Cause
Relying on direct child status (`proc.poll() is None`) to trigger process group termination, allowing detached or surviving descendants in the session to escape cleanup.

#### Remediation
1. **Unconditional Process Group Termination:** Saved `saved_pgid = proc.pid`. In the `finally` block of `_run_bounded_process()`, `_terminate_process_group()` unconditionally executes:
   ```python
   try:
       os.killpg(saved_pgid, signal.SIGKILL)
   except OSError:
       pass
   ```
2. **Reaping Direct Child:** Checks `if proc.poll() is None: proc.kill(); proc.wait(timeout=1)` to avoid zombie processes.
3. **Closing Descendant Pipes:** Even if a descendant closes inherited pipes or detaches stdout/stderr, `_terminate_process_group()` runs in `finally`, terminating all descendants before `_run_bounded_process()` returns.
4. **Race-Free Scratch Cleanup:** Because all descendants in `saved_pgid` are terminated with `SIGKILL` before `_run_bounded_process()` exits, `shutil.rmtree(run_scratch)` in `dispatch()` executes without racing against active processes holding open file handles.

#### Verification
- `test_r06_parent_exit_terminates_background_grandchild`: Parent spawns Grandchild running `sleep(30)` and exits immediately. Grandchild PID is verified dead (`os.kill(gpid, 0)` raises `OSError` / `ESRCH`).
- `test_r06_grandchild_closing_pipes_terminated`: Grandchild closes stdout/stderr and runs `sleep(30)`. Verified terminated cleanly without hanging.

### Finding R-07: Incomplete Authorization Binding, Instance-Local Replay, and Telemetry Exposure
- **Vulnerability Identifier:** R-07
- **Component:** `runtime_host_adapter.py` (`ApprovalStore`, `IsolatedHostAdapter.dispatch`) and `execution_profiles.py`
- **Preliminary Severity:** Medium
- **Confirmed Severity:** Medium
- **Classification:** `confirmed`

#### Suspected Weakness
1. **Instance-Local Replay:** Replay protection was previously stored in `self._dispatched_approvals = set()`. Replay across a new adapter instance or another host process succeeded.
2. **Telemetry Argument Disclosure:** Raw command arguments were logged in telemetry events (`event["command"]`), risking disclosure of sensitive tokens or paths.
3. **ExecutionSpec Timing:** `ExecutionSpec` was generated after authorization rather than binding parameters before verification.

#### Safe Reproduction
1. Dispatched an approved request on `adapter1`. Instantiated `adapter2 = IsolatedHostAdapter(...)` and dispatched the same approval. `adapter2` executed the replayed approval.
2. Command containing `--token=SECRET_KEY` logged the secret key string in plaintext in `adapter.events`.

#### Root Cause
In-memory instance-local state without shared/persistent single-use registry; logging raw argument vectors without sanitization.

#### Remediation
1. **`ApprovalStore` Registry:**
   - Implemented thread-safe `ApprovalStore` with `threading.Lock()`.
   - Process-wide singleton `_GLOBAL_APPROVAL_STORE` prevents cross-instance replay in the host process.
   - Optional file-backed storage with atomic file locking (`fcntl.flock(LOCK_EX)`) prevents cross-process replay.
   - Key binds `(request_id, authorization_ref, spec_sha256)`.
2. **Prioritized Spec Binding:**
   - `ExecutionSpec` is constructed BEFORE `assess()` and binds `(target, revision, command, cwd, effect, profile, operation, destination, paths, env_keys, timeout, max_bytes, authorization_ref)`.
   - `HostAttestation` extended with optional `spec_sha256: str = ''`.
   - `assess()` verifies `authority.spec_sha256 == request.get('spec_sha256')`.
3. **Telemetry Sanitization:**
   - Raw command arguments are excluded from `adapter.events` and `event["spec"]`.
   - Telemetry records `executable` (binary basename), `command_sha256` (cryptographic hash), `command_arg_count`, and `spec_sha256`.

#### Verification
- `test_r07_cross_instance_replay_rejected`: Approval consumed on `adapter1` is rejected on `adapter2` with `"authorization replay rejected: approval already consumed"`.
- `test_r07_file_backed_approval_store_atomic_replay_prevention`: File-backed `ApprovalStore` prevents duplicate consumption across instances.
- `test_r07_telemetry_sanitizes_command_arguments`: Commands with sensitive flags (e.g. `--api-secret-key=...`) verify that secret strings do not appear in telemetry events.
- `test_r07_spec_digest_mismatch_invalidates_authorization`: Tampered `spec_sha256` blocks dispatch before process creation.
