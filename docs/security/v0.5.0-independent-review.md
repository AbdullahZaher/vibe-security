## 2. Validation Details for Candidates C1–C4

### C1: `seal_evidence` Directory Check/Use Race
- **Investigation**: Tracing `seal_evidence.collect()` showed `review_dir.is_symlink()` and `is_dir()` followed by `iterdir()` and per-file path opens with `_validate_private_source()`. Because `O_NOFOLLOW` only protects the leaf file component, an attacker swapping `review_dir` between check and open could bypass containment.
- **Reproduction**: Replaced `review_dir` with a directory symlink; pre-fix `collect()` followed the link.
- **Fix**: Open `review_dir` using `os.open(review_dir, os.O_RDONLY | os.O_NOFOLLOW | getattr(os, "O_DIRECTORY", 0))` to bind a descriptor `dfd`. Read directory contents via `os.listdir(dfd)` and pass `dir_fd=dfd` to `_validate_private_source()` so child files are opened strictly relative to the verified directory descriptor without path traversal.
- **Regression test**: `test_refuses_symlink_review_dir` in `skills/prelaunch-security-audit/tests/test_evidence_sealing.py`.

### C2: `trusted_root` Assumptions on Owner-Writable Parents
- **Investigation**: In `audit_artifacts.py:trusted_root()`, the condition `immutable_parent = (parent.st_mode & 0o022) == 0 and (euid == 0 or parent.st_uid != euid or not parent.st_mode & 0o200)` accepted non-root owned directories with mode `0555` or owned by other users. An unprivileged owner can `chmod u+w` their own directory and replace symlinks.
- **Reproduction**: Constructed a user-owned directory with mode `0555` containing a symlink. Pre-fix code accepted the symlink root.
- **Fix**: Restricted system symlink parents strictly to root: `parent.st_uid == 0 and (parent.st_mode & 0o022) == 0 and link.st_uid == 0`. Only root-owned, non-world/group-writable directories (such as macOS `/var -> /private/var`) qualify.
- **Regression test**: `test_owner_readonly_directory_symlink_rejected` in `skills/prelaunch-security-audit/tests/test_artifact_io.py`.

### C3: Git Observation Commands Invoking Repository-Configured Helpers
- **Investigation**: `action-policy.json` included bare `git status`, `git status --short`, `git diff --no-ext-diff`, and `git diff --no-ext-diff --stat` as automatically allowed passive observations. In Git, `git status` executes repository-configured `core.fsmonitor` hooks, and `git diff --no-ext-diff` executes `diff.<driver>.textconv` filters defined in `.git/config` and `.gitattributes`.
- **Reproduction**: Configured `core.fsmonitor` and `diff.evil.textconv` in a test repository and ran `git status` and `git diff --no-ext-diff`; confirmed arbitrary command execution.
- **Fix**: Updated `allowed_observe_commands` in `action-policy.json` to require explicit hardening flags: `git -c core.fsmonitor=false status`, `git -c core.fsmonitor=false status --short`, `git rev-parse HEAD`, `git -c core.fsmonitor=false diff --no-ext-diff --no-textconv`, and `git -c core.fsmonitor=false diff --no-ext-diff --no-textconv --stat`. Bare, unhardened commands default to `ask`.
- **Regression test**: `test_unhardened_git_observation_requires_review` in `skills/prelaunch-security-audit/tests/test_plan_guard.py`.

### C4: Coverage Evidence Containment when `--source-root` is Omitted
- **Investigation**: In `validate_coverage.py`, the containment check requiring retained evidence artifacts to reside outside the target repository was enclosed in `if source_root is not None:`. If a coverage ledger contained evidence artifacts and `--artifact-root` was provided but `--source-root` was omitted, the containment check was skipped entirely.
- **Reproduction**: Passed coverage evidence containing an artifact without `--source-root`; pre-fix code checked the artifact hash without checking containment.
- **Fix**: Added `require(source_root is not None, "source root required to verify evidence containment")` whenever `proof["artifact"] is not None`.
- **Regression test**: `test_coverage_artifact_requires_source_root_for_containment` in `skills/prelaunch-security-audit/tests/test_audit_inventory_coverage.py`.

## 3. Rejected candidates

The reviewer rejected the following as not vulnerabilities, because they are documented fail-closed behavior or existing compensating controls:

- Failed executed tests count as assessment (intentional, documented).
- All-clear downgraded to `conditional launch` when a coverage test fails (intentional).
- `evaluate_trial_matrix` CLI never marks release-ready without authenticated real-Agent evidence (fail-closed by design).
- Host attestations are API inputs, not JSON-file approvals (documented trust boundary).
- `StaticHost` is not an OS sandbox (documented read-only broker).
- `plan_guard` is advisory only (documented).
- Self-claimed verification logs are not authenticated by `render_report` (structural-only check).
