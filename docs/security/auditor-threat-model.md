# Auditor threat model

**v0.6 development line, unreleased**

Draft current-implementation map at base `0750bf689b2783c5dd878b9eb821122629b6a9e1`; owner review pending. Status and decisions belong in [STATUS.md](../STATUS.md), not in a second release-status narrative. This file is derived from the linked source/tests, not the absent historical draft.

Trusted boundaries are the owner/host instruction and permission channels, reviewed controller code, and host-retained evidence. Target files, filenames, configs, scanner/tool output, model output and submitted JSON are untrusted data. A hash, callback label, model assertion or this document cannot authenticate consent or execution.

Shared state meanings in this document and STATUS.md:
- `implemented_tested`: implemented control with passing test evidence for the stated narrow scope; not independent assurance.
- `implemented_unverified`: code exists, but executed tests do not establish the named capability in the stated scope.
- `external_host_required`: authentic authority, enforcement or evidence must be supplied by a trusted external host; not a bundled guarantee.
- `proposed`: the named control or interface is not implemented.
- `unsupported`: no supported bundled capability is provided.

Control ownership is explicit; an external-host requirement is never a bundled guarantee. Step 1 tests used an external audit guard and synthetic fixtures; the guard is not shipped product code or OS-isolation evidence.
