# Skill and harness threat model — v0.5.0

Trusted boundaries are the owner instruction channel, host permission enforcement,
reviewed Skill/controller code, and separately retained source/evidence supplied by
an authorized operator. Repository text, package scripts, findings JSON, scanner
output, model responses and purported approval flags are untrusted inputs.

| Threat | Required defense | Residual limitation |
|---|---|---|
| Repository/tool prompt injection | Treat text as data; enumerate architecture before controls; no data-derived approvals | Prompts cannot enforce host permissions |
| Package hooks, shell injection, confused deputy | Static-only default; exact target/action permission and separate OS isolation | Arbitrary target execution requires a host adapter, not plan_guard |
| Path traversal, symlink or oversized evidence | Bounded regular-file reads, reject ambiguous paths and links, immutable Git source checks | An actively hostile host can replace trusted code/data |
| Forged PASS or copied finding evidence | Strict schemas, unique IDs, revision/actor/resource/subject binding and meaningful methods | Structural validation cannot authenticate arbitrary supplied logs |
| Missed attack surfaces | Explicit discovery limits, inventory denominator separate from ledger completeness | No generic static inventory proves exhaustive deployment discovery |
| Fake independent review | Distinct reviewer/context plus separately verified host provenance | Host provenance must be independently reviewed |
| Stale regression results | Source revision, pre/post evidence and impact invalidation | Opaque deployment drift remains unknown |
| Fix weakens tenant/role isolation | Preserve invariant identity, baseline regression and adjacent-role/tenant results | Unexercised state/concurrency combinations remain limitations |
| Secret leakage | Offline defaults, no automatic upload; redaction and private evidence storage | Automated redaction is incomplete; human review before sharing |
| Fabricated evaluation success | Completed genuine trials, independent adjudication, host logs; release fail-closed | No real-model quality claim without authorized trials |

Only synthetic fixtures and public-safe summaries belong in this repository.
Hashes detect changed bytes; they prove neither execution nor truth. A runtime
fingerprint is diagnostic identity, not proof of context or machine independence.
No new component can grant permission, deploy, or make production changes.
