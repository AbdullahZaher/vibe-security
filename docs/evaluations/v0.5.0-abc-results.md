## 1. Executive result

No general-purpose Agent, baseline Skill or candidate Skill trial was run against
a real target. Therefore:

- there are no true-positive, false-positive, false-negative, precision, recall,
  severity, calibration or coverage results;
- there is no evidence that v0.5.0 detects more real vulnerabilities than v0.4.0
  or a general Agent;
- there is no evidence that v0.5.0 reduces false positives in real repositories;
- the software implementation and its negative controls were tested, but that is
  not a measurement of security effectiveness.

The correct statement is: **software implementation verified within the tested
scope; real-world security effectiveness not yet validated.**

## 2. What was actually executed

### 2.1 Unit and contract tests (not trials)

Command, from the repository root on macOS 15.7.3 / arm64 / Python 3.13.7:

```sh
python3 -m unittest discover -s skills/prelaunch-security-audit/tests -v
```

Result at `c557b76`: **224 tests, 223 passed, 0 failed, 1 skipped, exit 0.**
The skip is the optional MCP SDK interoperability test because `mcp` is not
installed. These tests exercise validators, report gates and fixed synthetic
fixtures. They do not execute a model and cannot support a performance claim.

The pre-fix baseline on the same host was **219 tests, 2 failures, 6 errors,
1 skipped, exit 1**. All eight failures were caused by the macOS `/var` system
symlink being rejected by the artifact reader. That is a portability defect, not
a security finding; it is documented in
`docs/security/v0.5.0-remediation-verification.md`.

## 4. Why real trials were not run

| Missing prerequisite | Impact |
| --- | --- |
| Approved model access and spending limit | No inference could be requested |
| Privacy approval for sending repository source to a provider | Real targets could not be transmitted |
| Five owner-authorized, frozen disposable targets | No valid unseen holdout exists |
| Independent ground truth and adjudicators | No denominator for TP/FP/FN or severity |
| Verified arbitrary-code isolation adapter | Runtime testing on real targets is not safely available |
| Local model weights | A no-cost local pilot was not available |

Creating synthetic "targets", inventing answer keys or labeling synthetic
fixtures as real-world results would invalidate the comparison. That was not
done.

## 5. What the existing 20 synthetic cases can and cannot show

`evals/cases.json` contains 20 synthetic scenarios covering prompt injection,
tenant isolation, payment webhooks, MCP boundaries, evidence laundering and
similar controller behaviors. They are valuable as regression tests for the
harness and the Skill's safety instructions.

They are not:

- unseen targets;
- independent ground truth;
- evidence of real repository coverage;
- evidence of vulnerability recall or false-positive rates;
- a substitute for five architectures and independent adjudication.

## 6. Methodological limitations

Even once trials begin, the following must be reported:

- the five-target sample is small and cannot establish general-purpose
  performance;
- public target code may exist in model training data;
- reviewer judgment affects severity and matching;
- model/provider behavior can change between runs;
- runtime testing depends on the host's isolation quality;
- static-only conditions cannot verify deployed behavior;
- budgets and context limits truncate real audits.

## 7. Required next steps

1. Obtain written owner approval for model use, spending cap and source
   transmission (or provide a genuinely local model with tool-calling support).
2. Freeze five authorized target repositories and their authorization records.
3. Commission two independent reviewers to build and seal ground truth.
4. Freeze the candidate SHA and both Skill revisions per trial.
5. Run a small pilot (one case, three arms, three repetitions) on isolated
   contexts; inspect host logs before expanding.
6. Run the full randomized matrix with identical budgets and tools.
7. Adjudicate findings, evidence reproducibility and remediation independently.
8. Only then compute metrics and decide whether v0.5.0 improves real-world
   security outcomes.

## 8. Conclusion

The A/B/C comparison is **blocked, not passed**. The repository contains a
tested protocol, a working harness preflight and honest placeholders. It does
not contain real trial results, and this document does not imply any.
