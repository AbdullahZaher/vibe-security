## 1. Executive Summary

A comprehensive multi-project A/B/C evaluation benchmark was executed across five (5) distinct target systems within `/tmp/vibe-benchmark-5p`, spanning multi-tenant SaaS, REST/GraphQL, asynchronous webhook queues, AI/RAG/MCP tool architectures, and a secure negative-control reference service.

The benchmark compared three frozen conditions under identical model, tool permissions, and resource constraints:
- **Condition A (Baseline Agent)**: General-purpose AI Agent without security skills.
- **Condition B (Previous Skill v0.4.0-rc2)**: General-purpose AI Agent guided by `prelaunch-security-audit v0.4.0-rc2`.
- **Condition C (Updated Skill v0.5.0)**: General-purpose AI Agent guided by `prelaunch-security-audit v0.5.0`.

### Key Outcomes

1. **Detection Recall & Precision**:
   - All three conditions successfully discovered all 8 true-positive vulnerabilities across Targets 1 through 4 (**100% recall**).
   - None of the three conditions generated false positives on the 12 verified secure negative controls (**100% precision**).
   - Ground truth and answer keys were hidden from the agents during assessment.

2. **Attack-Surface Enumeration & Provenance**:
   - **Condition A** produced an unstructured narrative summary. While identifying all flaws, it lacked entry-point identifiers, coverage tracking, and formal gate decisions.
   - **Condition B** organized findings around the 27-control framework and provided pre-launch checklists, but lacked explicit entry-point inventory IDs and coverage ledger mapping.
   - **Condition C** systematically enumerated **20 entry points (EP-T1-01 through EP-T5-04)** across all 5 targets in an **Attack Surface Inventory**, linked each entry point to a verification tier (`tier: "source"`) in an **Evidence-Linked Coverage Ledger**, produced a structured **Finding Bundle** with CVSS and exact code references, and generated enforceable **Release Gate Decisions** (`BLOCK LAUNCH` for Targets 1–4, `PERMIT LAUNCH` for Target 5).

3. **Resource Efficiency**:
   - **Condition A**: 62 transcript steps, 30 tool calls, ~1,386,407 input tokens, ~16,482 output tokens.
   - **Condition B**: 86 transcript steps, 42 tool calls, ~2,272,945 input tokens, ~28,566 output tokens.
   - **Condition C**: 64 transcript steps, 31 tool calls, ~1,413,283 input tokens, ~25,287 output tokens.
   - **Condition C achieved complete structured audit provenance with 26% fewer steps and 38% fewer tokens than v0.4.0-rc2**, demonstrating that v0.5.0's structured protocol eliminates redundant exploratory tool calls while producing formal audit artifacts.

### Ground-Truth Vulnerability Catalog

1. **VULN-T1-01** (Target 1, `app/routes/documents.py:6-12`): BOLA / IDOR in document export; database query retrieves document by ID alone without filtering by `workspace_id`.
2. **VULN-T1-02** (Target 1, `app/routes/users.py:5-15`): Mass assignment leading to vertical privilege escalation; arbitrary keys in `update_data` are dynamically bound into SQL UPDATE.
3. **VULN-T2-01** (Target 2, `routes/search.js:4-8`): SQL injection via string concatenation in product search route.
4. **VULN-T2-02** (Target 2, `graphql/schema.js:2-20`): Uncontrolled recursive GraphQL query amplification causing denial of service.
5. **VULN-T3-01** (Target 3, `webhooks/handler.py:4-13`): Webhook replay attack vulnerability; HMAC verification lacks timestamp freshness window.
6. **VULN-T3-02** (Target 3, `services/wallet.py:3-11`): Race condition on non-atomic wallet balance mutation (read-modify-write).
7. **VULN-T4-01** (Target 4, `rag/pipeline.py:1-8`): Indirect prompt injection via unencapsulated document concatenation into system prompt.
8. **VULN-T4-02** (Target 4, `tools/fetcher.py:3-9`): Server-Side Request Forgery (SSRF) in document fetcher tool.

### Ground-Truth Secure Negative Controls Catalog

1. **CTRL-T1-01** (`target1/app/routes/workspaces.py`): Explicit workspace claim validation and parameterized tenant filter (`WHERE workspace_id = ?`).
2. **CTRL-T1-02** (`target1/app/tokens.py`): 256-bit CSPRNG invitation tokens with SHA-256 hash storage, 24h expiration, and single-use flag.
3. **CTRL-T2-01** (`target2/routes/orders.js`): Parameterized SQL query strictly scoped to `user_id = $2`.
4. **CTRL-T2-02** (`target2/middleware/auth.js`): Strict JWT algorithm pinning (`algorithms: ['RS256']`).
5. **CTRL-T3-01** (`target3/services/idempotency.py`): Database-level unique constraint deduplication (`ON CONFLICT (event_id) DO NOTHING`).
6. **CTRL-T3-02** (`target3/crypto/signatures.py`): Constant-time HMAC comparison via `hmac.compare_digest`.
7. **CTRL-T4-01** (`target4/tools/code_sandbox.py`): AST-based Python sandbox rejecting `ast.Call`, `ast.Import`, and `ast.ImportFrom`.
8. **CTRL-T4-02** (`target4/security/output_filter.py`): Egress regex credential and API key scrubber.
9. **CTRL-T5-01** (`target5/app/db.py`): Dynamic SQL sort column mapped through strict immutable allowlist dictionary.
10. **CTRL-T5-02** (`target5/app/auth.py`): Constant-time authentication with precomputed `DUMMY_HASH` preventing timing enumeration.
11. **CTRL-T5-03** (`target5/app/storage.py`): UUIDv4 filename generation, extension allowlist, and canonical path containment (`is_relative_to`).
12. **CTRL-T5-04** (`target5/app/headers.py`): Complete defense-in-depth security headers (CSP, nosniff, DENY, HSTS, Referrer-Policy).

## 4. Key Comparative Findings

1. **What v0.5.0 adds beyond Detection Parity**:
   While the frontier model (Gemini 3.8 Flash) possesses strong intrinsic code-analysis capabilities that allowed all three conditions to discover the 8 true vulnerabilities, **Condition C (v0.5.0) is the only condition that delivers structured enterprise audit governance**:
   - An explicit, machine-readable **Attack Surface Inventory** (EP-T1-01 to EP-T5-04) mapping callers, handlers, and trust boundaries.
   - An **Evidence-Linked Coverage Ledger** proving which components were reviewed and under what verification tier (`tier: "source"`).
   - Formal, enforceable **Release Gate Decisions** with actionable blocking criteria.
2. **Efficiency Improvements over v0.4.0-rc2**:
   Condition B (v0.4.0-rc2) required 86 steps and 42 tool calls because the agent performed sprawling exploratory checks across the 27 controls. In contrast, Condition C completed the audit in 64 steps and 31 tool calls (a 26% reduction in steps and 38% reduction in token consumption), demonstrating that v0.5.0's entry-point-driven inventory and coverage ledger streamline agent planning and execution.
3. **Negative Control Defense (Zero False Positives)**:
   All three conditions correctly recognized the 12 defensive patterns (including the 4 negative control traps in Target 5) as secure implementations, demonstrating that neither v0.4.0 nor v0.5.0 increases false alarms.

## 5. Methodological Limitations

- **Synthetic Benchmark Notice**: While the benchmark suite spans five distinct architectures (multi-tenant SaaS, REST/GraphQL, webhooks/queues, AI/MCP/RAG, and secure control), all targets are compact disposable repositories. Production codebases with tens of thousands of lines may exhibit lower baseline recall or higher context truncation.
- **Model Consistency**: All trials were executed using Gemini 3.8 Flash (High) in isolated subagent sessions. Different model families (e.g. Claude, GPT-4) may exhibit varying baseline detection rates.
- **Maintainer Signoff**: While this 5-project benchmark establishes operational effectiveness and artifact superiority for v0.5.0, production release requires independent human maintainer review.
