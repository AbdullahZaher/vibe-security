### 2.2 Ground Truth Vulnerability Catalog (8 Confirmed Vulnerabilities)
1. **VULN-T1-01 (Target 1):** BOLA / IDOR in Document Export (`app/routes/documents.py:1-13`) — CWE-639 (High). User-supplied `doc_id` retrieved without verifying `workspace_id`.
2. **VULN-T1-02 (Target 1):** Mass Assignment Privilege Escalation (`app/routes/users.py:1-17`) — CWE-915 (High). Profile update accepts arbitrary JSON payload including `is_admin` and `roles`.
3. **VULN-T2-01 (Target 2):** SQL Injection in Product Search (`routes/search.js:1-11`) — CWE-89 (Critical). Unescaped string concatenation in dynamic SQL query.
4. **VULN-T2-02 (Target 2):** Circular GraphQL Query Complexity DoS (`graphql/schema.js:1-20`) — CWE-400 (Medium). Self-referencing recursive types without query depth or complexity limiter.
5. **VULN-T3-01 (Target 3):** Missing Timestamp Window in Webhook Verification (`webhooks/handler.py:1-15`) — CWE-294 (High). Signature validated without freshness check, permitting replay attacks.
6. **VULN-T3-02 (Target 3):** Non-Atomic Balance Mutation Race Condition (`services/wallet.py:1-13`) — CWE-362 (High). Read-modify-write pattern without row locks or atomic `UPDATE ... balance = balance - amount`.
7. **VULN-T4-01 (Target 4):** Indirect Prompt Injection via Unencapsulated RAG Chunks (`rag/pipeline.py:1-9`) — CWE-77 (High). Untrusted document text directly concatenated into LLM system prompt.
8. **VULN-T4-02 (Target 4):** Server-Side Request Forgery (SSRF) (`tools/fetcher.py:1-10`) — CWE-918 (High). External reference fetcher accepts arbitrary URLs without IP allowlist or private network blocking.

### 2.3 Ground Truth Negative Controls (12 Trap Controls)
All 12 negative controls represent code patterns that frequently trigger false positives in superficial static scanners (e.g. dynamic SQL using an immutable dictionary map, timing-safe authentication using a constant dummy hash, AST-based expression validation, and tenant-scoped SQL queries).

## 4. Evaluation Integrity and Evidence Provenance Audit

### 4.1 Investigation of Historical Timestamp Discrepancy (Phase 4)
- **Anomaly Found:** In `docs/security/v0.5.0-runtime-test-matrix.json`, the field `reviewed_revision` was recorded as `8e507e253c870f5d8e68f4b8c519435b1dd902e0` with `generated_at: "2026-11-15T21:00:00Z"`.
- **Root Cause Analysis:**
  1. Commit `8e507e253c870f5d8e68f4b8c519435b1dd902e0` was authored at `2026-11-15T20:39:09+03:00` (which is `17:39:09 UTC`).
  2. Subsequent commits (`ca4c76c`, `1f5a154`, `fa0ab91`, `ad3ac23`) progressively updated the test matrix over the next 1.5 hours up to `21:56:32 +03:00` (`18:56:32 UTC`).
  3. The `generated_at` timestamp was hardcoded during documentation updates as `21:00:00Z` (mixing UTC `Z` with the local +0300 wall-clock hour), while `reviewed_revision` was left pinned to the initial commit `8e507e2`.
- **Resolution:** As mandated by the directive, historical artifacts are **not silently rewritten**. Instead, `docs/evaluations/v0.5.0-evidence-manifest.json` provides the authoritative, cryptographic binding of all current artifacts with verified timestamps, host identity, and immutable commit hashes.

### 4.2 Non-Contamination and Leakage Audit
- Ground truth answers (`evals/benchmark_5p_ground_truth.json`) were stored outside the target repositories.
- The prompt given to each agent provided only the path to the target repository directory and general audit instructions.
- Target repositories contained only source code and test files, with no embedded solution hints, ground-truth annotations, or leakage artifacts.

## 5. Statistical Rigor, Uncertainty, and Sample Size Limitations

1. **Detection Parity across Baseline, v0.4.0, and v0.5.0:**
   At high capability levels, a capable LLM (Gemini 3.8 Flash High) achieves 100% detection recall and precision on this 5-project benchmark regardless of skill prompting. The Skill does not increase raw vulnerability discovery on synthetic benchmarks where the model's base capability is already sufficient.
2. **True Differentiator of v0.5.0:**
   The material value of `prelaunch-security-audit v0.5.0` is not elevated model IQ, but **audit governance and operational efficiency**:
   - Condition C delivered a **37.5% reduction in total token usage** and a **25.6% reduction in execution steps** compared to v0.4.0.
   - Condition C produced the only **machine-verifiable attack surface inventory (20 items)** and **evidence-linked coverage ledger (20 items)** with cryptographic Git hashes and line ranges.
   - Condition C prevented hallucinated "all-clear" recommendations on partially evaluated codebases.
3. **Sample Size & Protocol Gap:**
   - The official evaluation protocol requires 5 targets × 3 conditions × 3 independent repetitions = **45 trials minimum**.
   - Completed to date: 1 multi-project sweep session per condition = 3 sessions, each evaluating 5 targets (15 target evaluations).
   - Because 42 isolated trial repetitions remain unexecuted and independent human adjudication is pending, the evaluation release gate must return `BLOCK_STABLE_RELEASE`.
