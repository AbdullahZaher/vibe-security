## 3. Mandatory Blocking Issues for Stable Release

The following gates are currently blocking stable release certification:

1. **Gate 10 — Independent Human Maintainer Authorization:**  
   In compliance with the project charter and governance rules, AI agents cannot approve or sign off on production releases. Only an authorized human repository maintainer can grant stable release publication.
2. **Gate 5 — Statistical Evaluation Matrix Completion:**  
   The protocol mandates 45 independent trials (5 cases × 3 arms × 3 repetitions). While 1 full sweep across all 5 targets was executed per condition (15 target evaluations), 42 repetitions remain unexecuted due to external inference budget constraints and authorization controls.
3. **Gate 9 — Repository Branch Protection Enactment:**  
   The repository owner must verify that the GitHub repository branch protection rulesets on `main` and `feat/prelaunch-security-audit-v0.5.0-plan-20261114` enforce:
   - Require a pull request before merging (minimum 1 approved review from a human security maintainer).
   - Require status checks to pass before merging (`unit-and-contract`, `mcp-stdio-integration`).
   - Require signed commits.
   - Require linear history (no merge commits, rebase or squash only).
   - Do not allow bypass of the above settings.

## 4. Rollback and Recovery Plan

In the event of an unexpected regression, emergency, or post-release issue:

### Immediate Mitigation (Within 15 minutes)
1. **Revert PR or Feature Branch:**  
   Revert the merge commit on the target branch using standard git revert:
   ```bash
   git revert -m 1 <MERGE_COMMIT_SHA> -m "revert: rollback v0.5.0 release due to regression"
   git push origin <TARGET_BRANCH>
   ```
2. **Fail-Closed Default Protection:**  
   Because `IsolatedHostAdapter` already defaults to `RUNTIME_EXECUTION_ENABLED = False`, any attempted untrusted code execution automatically fails closed without executing commands.
3. **Revoke Approvals:**  
   In an emergency where approval store credentials or tokens are suspected of compromise, delete the local approval store file:
   ```bash
   rm -f ~/.vibe-security/approvals.json ~/.vibe-security/approvals.json.lock
   ```
   All subsequent dispatch requests will immediately require re-authorization.

### Post-Incident Recovery
1. Identify the root cause via the cryptographic evidence manifest and git history.
2. Construct a reproducer test in `skills/prelaunch-security-audit/tests/test_independent_release_blockers.py`.
3. Require full re-verification of all 10 negative tests on macOS host prior to any re-release.
