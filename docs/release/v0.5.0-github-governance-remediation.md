### Required administrator change: creation-only gate, without breaking immutability

**Keep existing ruleset 27351357 unchanged.** Its update/deletion restrictions and empty bypass list prevent ordinary mutation/deletion of existing release tags.

In GitHub **Settings → Rules → Rulesets**, add a **separate** active **tag ruleset**:

- Suggested name: `Restrict v* Release Tag Creation`
- Target: `Tag`; include `refs/tags/v*` (or the exact equivalent GitHub UI pattern); exclusions: none
- Enable **Restrict creations** **only**
- Do **not** select `Restrict updates` or `Restrict deletions` in this *additional* ruleset: combining those with publisher bypass would accidentally grant the same publisher tag-mutation permissions
- Bypass list: **one explicitly named, separately authorized Release Publisher identity** (an appropriately scoped GitHub App or named release-owner user, if supported by the plan); never grant blanket Write/Maintain/RepositoryAdmin role bypass without a documented owner risk decision
- Enforcement: `Active`
- Require independent human release-owner permission before the publisher invokes tag creation. A ruleset publisher exception is **not** an automatic release authorization
- Consider protecting release assets/workflows separately and requiring verified artifact attestation before publication

The exact release publisher identity is intentionally **not invented** in this handoff. The repository owner must choose and review that identity and privilege level. **Do not create a no-bypass creation rule unless intentionally making all v* tag creation impossible.**
